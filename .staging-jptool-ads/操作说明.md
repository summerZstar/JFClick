# 切换到 jptool-vite 工作区后的操作说明

本目录（`.staging-jptool-ads/`）是从 JFClick 工作区生成的一次性交付包，
用于把「广告点击统计 + KV 计数」落到 jptool-vite 项目。文件路径已按 jptool-vite 的目录结构摆好。

## 一、背景 / 你要做什么

之前你的广告配置 `edge-functions/*/ad.js` 的 `url` 是直接跳到 `https://jptool.cn`，没有点击统计。
现在改成：客户端点击广告 → 走一个统计中转路由（`/…/ad/go?id=<adId>`）→ 服务端在 KV 里给该广告 `+1` 点击 → `302` 跳回真实落地页。

1. **客户端一行不用改**：因为落地地址只在 `go.js` 的 `TARGETS` 里，`ad.js` 下发的只是中转链接。
2. **顺手去掉了 `tag` 角标**：横幅上不再显示"自营"角标（`tag` 字段已删除）。
3. **id 编号表已写进注释**：`ad-<渠道>-<编号>`，自营用 `self`、未来外部广告主用 `ext`，方便你后台对账。

## 二、切工作区

1. 在 TraeCode 里把当前工作区切成（或新开）`D:\work\code\zyh\jptool-vite`。
2. 到那里后，把本目录 `edge-functions/` 下的文件按对应位置**覆盖 / 新增**即可（见下表）。

## 四、关键前置：EdgeOne 控制台绑定 KV（一次性）

计数依赖 KV 存储，**必须先绑定一次**，否则计数不生效（但跳转照常，不影响功能）：

1. 控制台 → **Pages → 存储 → KV 存储** → 立即申请开通账户。
2. **创建命名空间**，任意取名（如 `jptool-ads`）。
3. 在该命名空间 **绑定本项目**（jptool-vite），**绑定变量名填 `AD_KV`** —— 代码里硬编码引用这个名字，不能改。
4. 未绑定时的降级行为：直接 302 跳转，只是不计数。

## 五、验证

切到 jptool-vite 后：

1. `npm run build`，确认 `dist/edge-functions/jfclick/ad.js`、`dist/edge-functions/jfapi/ad.js` 存在。
2. 上传 `dist/`，访问确认：
   - `GET https://jptool.cn/jfclick/ad` 返回 200 且条目含 `id` 与中转 url。
   - 浏览器打开 `https://jptool.cn/jfclick/ad/go?id=ad-jfclick-self-01`，应 `302` 跳到 `https://jptool.cn`。
   - 多刷新几次后，到控制台 KV 里看 `jfclick:ad:ad-jfclick-self-01:clicks` 是否为 0 以上的递增数。

## 六、后续改广告（不用发客户端版）

- 改文案 / 关闭广告位：只改对应 `ad.js` 里的 `AD_CONFIG`，重部署即可。
- 换落地地址：只改对应 `go.js` 的 `TARGETS`；`ad.js` 里的中转 url 不用动。
- 加外部广告主：在 `ad.js` 加条目（`id` 用 `ext` 前缀）+ 在 `go.js` 的 `TARGETS` 加同一 key，两处同步。
- 查点击量：控制台 KV 看 `<程序>:ad:<id>:clicks`。
